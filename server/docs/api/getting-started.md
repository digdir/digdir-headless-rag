# Getting Started with the Digdir RAG API

This guide will help you make your first API request and understand the basics of working with the Digdir RAG API.

## Prerequisites

Before you begin, you'll need:

1. **An API Key** - Contact your administrator to obtain an API key
2. **HTTP Client** - cURL, Postman, or any HTTP library in your preferred language

## Your First Request

Let's make a simple RAG query to ask a question about Norwegian regulations.

### Using cURL

```bash
curl -X POST https://admin.kunnskap.digdir.cloud/api/rag \
  -H "Content-Type: application/json" \
  -H "X-API-Key: rag_your_api_key_here" \
  -d '{
    "query": "Hva er Altinn?"
  }'
```

### Using JavaScript (fetch)

```javascript
const response = await fetch('https://admin.kunnskap.digdir.cloud/api/rag', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-API-Key': 'rag_your_api_key_here'
  },
  body: JSON.stringify({
    query: 'Hva er Altinn?'
  })
});

const data = await response.json();
console.log(data.answer);
```

### Using Python (requests)

```python
import requests

response = requests.post(
    'https://admin.kunnskap.digdir.cloud/api/rag',
    headers={
        'Content-Type': 'application/json',
        'X-API-Key': 'rag_your_api_key_here'
    },
    json={
        'query': 'Hva er Altinn?'
    }
)

data = response.json()
print(data['answer'])
```

## Understanding the Response

A successful RAG request returns:

```json
{
  "answer": "Altinn er en digital plattform...",
  "conversation-id": "abc123xyz",
  "model": "gpt-4o-2024-11-20",
  "chunks-used": [
    {
      "chunk-id": "chunk_001",
      "doc-title": "Om Altinn",
      "doc-num": "doc_123",
      "content-markdown": "# Altinn\n\nAltinn er..."
    }
  ]
}
```

| Field | Description |
|-------|-------------|
| `answer` | The LLM-generated answer to your question |
| `conversation-id` | Unique ID for this conversation (use for follow-ups) |
| `model` | The LLM model used for generation |
| `chunks-used` | Source documents used to generate the answer |

## Choosing Between /api/rag and /api/retrieve

The API offers two main endpoints for querying:

### /api/rag - Full RAG with LLM Generation
Use this when you want a complete answer generated by the LLM.

```bash
curl -X POST .../api/rag \
  -H "X-API-Key: ..." \
  -d '{"query": "Hva er Altinn?"}'
```

**Returns**: Generated answer + source chunks

### /api/retrieve - Retrieval Only
Use this when you want to handle LLM generation yourself, or just need the relevant documents.

```bash
curl -X POST .../api/retrieve \
  -H "X-API-Key: ..." \
  -d '{"query": "Hva er Altinn?", "top_k": 5}'
```

**Returns**: Ranked chunks with relevance scores (no LLM answer)

## Continuing a Conversation

To continue an existing conversation, include the `conversation-id` from the previous response:

```bash
curl -X POST .../api/rag \
  -H "X-API-Key: ..." \
  -d '{
    "query": "Kan du forklare mer?",
    "conversation-id": "abc123xyz"
  }'
```

The API will use the conversation history to provide contextually relevant answers.

## Handling Errors

The API returns standard HTTP status codes:

| Status | Meaning |
|--------|---------|
| 200 | Success |
| 400 | Bad request (missing required field, invalid format) |
| 401 | Unauthorized (invalid or missing API key) |
| 404 | Not found (entity or conversation doesn't exist) |
| 429 | Rate limited (too many requests) |
| 500 | Server error |

Error responses include a message:

```json
{
  "error": "Missing required field: query"
}
```

## Optional Parameters

### RAG Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `query` | string | *required* | Your question |
| `conversation-id` | string | auto-generated | Continue existing conversation |
| `model` | string | `gpt-4o-2024-11-20` | LLM model to use |
| `rerank-top-k` | integer | entity config | Max chunks to rerank |
| `context-top-k` | integer | entity config | Max chunks for context |

### Retrieve Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `query` | string | *required* | Your search query |
| `top_k` | integer | 10 | Number of chunks to return |
| `include_query_expansion` | boolean | true | Use LLM to expand query |
| `filter` | object | none | Filter by document metadata |
