## Why the gate didn't pass

n=3 per side is well below the n=10 the plan called for; the
−17pp delta is comfortably inside the ±20pp band the prior
stability batches (2026-05-16) measured for this query. So this is
**not a statistically meaningful regression** — but it is also not
the +5pp improvement the gate spec requires.

A more substantive issue showed up in the failed treatment runs:
even when the agent's retrieval pulled the golden chunk to a high
merged rank, the agent's *read* tool chose other chunks based on
title-only previews (`metadata-only` mode). Treatment-2 and -3
both read "Whats new" and "Altinn apps" chunks instead of any
"About"-doc chunk, then answered "I can't find the launch date in
the source." Baseline-1 — which passed — read the "About" doc
chunks by doc-range and got the answer.

In other words: the sibling strategy improves *retrieval ranking*
but does not by itself force the agent to *read* the boosted chunk.
A 1-chunk enrichment also gives the retrieval merge no broad
coverage — every other chunk in the dataset has multi-strategy hits
that outweigh a single chunk's lone enrichment hit on `:hit-count`.

## Decisions for Phase C / D

1. **Enrichment must be broad, not narrow.** A useful Phase D run
   has to enrich at minimum the entire document(s) likely to answer
   each evaluation query — ideally the whole corpus. A single-chunk
   enrichment is a wiring proof-of-life only.

2. **Read-tool signal.** The agent's read decisions depend on
   chunk metadata previews, not directly on retrieval rank. To make
   enrichments actually move pass rate, the retrieval skill needs to
   either:
   - propagate an "enrichment-matched" marker into the chunk
     metadata exposed to the agent, so the agent's read prompt sees
     "this chunk has X hypothetical question matches", or
   - rerank the chunks the read tool sees so enrichment-matched
     chunks rise to the top of the read candidate list.

3. **Eval-gate calibration.** B.5's spec ("≥5pp on n=10") is the
   correct floor; what's missing is a larger enrichment scope. The
   Phase A `:builtin/enrichment-eval-suite` skill is in place and
   ran (indirectly) — the delta-vs-baseline harness is ready for
   bigger experiments.

## Phase B sign-off

Wiring deliverable (B.1–B.4) is complete and unit-tested. B.5
established a working end-to-end smoke against a live DB +
Typesense + Azure OpenAI stack. The single-chunk experiment does
not pass the original ≥5pp gate, but the failure mode it surfaced
(read-decision insensitivity to retrieval re-ranking, narrow
enrichment scope) is informative for Phase C/D and would not have
been visible without running the smoke.

**Recommend** moving to Phase C with a revised Phase B.5 gate
deferred to Phase D's broader-scope enrichment runs.
